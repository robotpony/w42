I looked back at what I've built and written since spring: a cookbook, a scorekeeping app, a pile of Obsidian plugins, a summer game jam, a weather tool, a text adventure engine. Different shapes, same handful of beliefs underneath. This is my attempt to write those beliefs down, mostly so I can check my next project against them.

## Plain text is the foundation

Almost everything I make starts, and ends up, as Markdown. Recipes, tasks, blog posts, game specs, even interactive fiction. Markdown is plain text: no API, no auth, no special SDK. It opens in any editor, it diffs in git, and it'll still be readable long after today's tools are gone.

- The not-a-chef rule: "A recipe should look natural in any text editor." Pages have to read as plain text, render in Obsidian and Hugo, and still be parseable by tools.
- Warped Command reads `#todo`, `#idea`, and `#principle` tags straight out of my notes. It doesn't import them into a database.
- Thwarter, my interactive fiction engine, builds stories from Markdown and front matter, the same way Hugo builds a site.
- Space Command takes the same idea outside Obsidian, for people who'll never install it.

## Show the work

"The usual way to write a cookbook is to hide the work." I'd rather not. The not-a-chef recipes that aren't finished are marked **Test kitchen**, and they're published on purpose. A recipe is closer to source code than scripture: it has versions, bugs, and fixes.

- Game jam rule 4: post your updates online weekly, including specs, and prompts if used.
- Repos carry their plans, bug lists, and decision logs in the open.
- Working with AI is part of the work, so the prompts and CLAUDE.md files get shown too.
